# PearPlay control contract v1

Native Messaging is control only. Media is fetched directly by the receiver; no relay or cookies are transferred. This contract is shared by `extension/` and `helper/`. Changes incompatible with v1 require a new version, not silent field reinterpretation.

## Framing and trust

Native Messaging uses a native-endian unsigned 32-bit byte-length prefix followed by UTF-8 JSON. Each message is at most 65,536 bytes. Reject invalid lengths, malformed JSON, unsupported versions, unknown operations, unexpected keys and invalid field types. Host name: `com.pearplay.helper`. Installation allowlists an exact `[a-p]{32}` extension ID; the runtime independently checks the exact `chrome-extension://ID/` origin. No wildcard origins.

## Requests

Every request has exactly `v`, `id`, `op`, `args`:

- `v`: integer `1` (not boolean).
- `id`: 1–64 ASCII letters, digits, underscores or hyphens.
- `op`: `hello`, `discover`, `start`, `status`, `stop`, `pause`, `resume`.
- `args`: object, constrained below.

| Operation | Arguments |
|---|---|
| hello, status, stop, pause, resume | `{}` |
| discover | `{}` or `{ "host": "literal IPv4 or IPv6 address" }` |
| start | `{ "receiver": "discovered identifier", "host": "literal IP", "url": "exact HTTP(S) URL" }` |

URLs are bounded to 16,384 characters. Preserve original text, including percent escapes, case, query order and fragment. Reject whitespace, controls, backslashes, missing host, credentials in authority and invalid ports. Never put real media URLs in argv, source, logs, reports or persistent browser storage. A parsed URL may be used for validation and a hostname-only display, never as a normalized replacement for the original.

`start` requires explicit candidate and receiver selection. Receiver host is a discovery hint, not an override of paired identity. This prototype may support one paired receiver at a time. Pairing is owned by the helper and may use its terminal CLI with hidden PIN entry; credentials never traverse Native Messaging.

## Responses and events

Responses contain `v: 1`, matching `id`, `ok` (boolean), `state`, `evidence`, and `capabilities` (operation strings). Optional `receivers` is a bounded array of `{identifier,address,label}`; optional `error` is a static sanitized error code. Never forward upstream exception text, arbitrary device properties, raw URLs or protocol payloads. Asynchronous state notifications use `id: "event"`.

States: `idle`, `connecting`, `playing`, `paused`, `stopping`, `stopped`, `error`.
Evidence: `none`, `protocol`, `unverified`.

HTTP acceptance alone must not become `playing`. A validated receiver playback event can yield `playing` with `evidence: "protocol"`; it is still not proof of visible video or audible sound. A stop command accepted without receiver confirmation must retain unverified evidence. Disconnects invalidate pending operations and expose an error/recovery state. Capability advertisement must not imply controls have been human-verified.

## Local playback and recovery

Do not automatically pause local playback on command acceptance. The prototype uses explicit user confirmation of TV video/audio before pausing the specifically selected local video. Local resume remains available after errors or native disconnection. Navigation invalidates previous document candidates and must not pause a replacement page's video.

## Compatibility gate

Automated contract tests and protocol events are separate from browser integration and human TV observations. Full prototype acceptance requires Chrome and Brave individually, FOX video/audio through this integration, an actual observed ad/program transition with Pi-hole blocking temporarily disabled, and lifecycle/error/uninstall evidence. No elapsed-time or mock result substitutes for these observations.
